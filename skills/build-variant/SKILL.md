# Build a variant

Implement only the assigned direction and shared constraints in the confirmed scratch surface. Use real surrounding components and navigation where useful for comparison, but avoid production integrations or unrelated refactors unless the brief calls for them. Keep your work isolated from other variants and from shipping code. Observe the repository's run and data permissions.

Report where the variant can be viewed, which choices it illustrates, what was not exercised, and any surprising constraint. Leave interactive UI exercise to the human rather than driving it yourself. Do not start app dev/build commands or commit without explicit human confirmation. Flag an assignment that requires changing the agreed scratch location or product direction before proceeding. Do not decide which candidate wins, turn the prototype into a feature, or claim UI behavior that has not been experienced by the human.
